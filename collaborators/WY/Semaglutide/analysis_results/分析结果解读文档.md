# Semaglutide 小鼠模型多组学联合分析结果解读

> 本文档系统说明各层次分析结果文件的含义与解读方法，适用于 Lung（肺）、BO（肠道/Gut）、Oral（口腔）三个部位的转录组分析以及以 Oral 为中心的宿主-微生物组联合分析。
>
> **实验设计**：四组小鼠 — WT_Control（野生型对照）、WT_Treated（野生型+索马鲁肽）、DB_Control（db/db 糖尿病模型）、DB_Treated（db/db+索马鲁肽治疗）。核心关注轨迹：WT_Control → DB_Control → DB_Treated，即疾病发生与药物干预的过程。

## 第一部分：转录组分析 {#part1}

**结果目录**：`analysis_results/RNA/{Lung,BO,Oral}/`

### 1.1 质量控制图

#### `PCA.pdf / PCA.png`

主成分分析（PCA）图，每个点代表一个样本，颜色区分实验组别。

**解读要点**：
- PC1 和 PC2 通常解释最大的组间变异。若不同实验组（WT vs DB）在 PC1 轴上分离明显，说明疾病状态对转录组有显著影响。
- DB_Treated 样本的位置若落在 WT_Control 与 DB_Control 之间，提示药物治疗使转录组部分恢复。
- 同一组内各样本点聚集紧密，表明组内重复性好；若某样本明显偏离，需确认是否存在技术异常。
- WT_Treated 的位置反映药物对健康小鼠自身转录组的影响（理想情况下应接近 WT_Control）。

#### `Sample_Distance_Heatmap.pdf`

基于 VST 归一化后欧几里得距离的样本间距离热图。

**解读要点**：
- 颜色越深（通常越蓝）= 两样本距离越近、转录组越相似。
- 同组样本相互间距离小（热图中聚在一起），形成沿对角线分布的深色方块。
- 若 DB_Treated 组的样本与 WT_Control 间距离小于与 DB_Control 间的距离，定量支持治疗后的恢复现象。

### 1.2 LRT 多组差异分析

#### `LRT_results_all.csv`

对所有经过低表达过滤后的基因，使用 DESeq2 似然比检验（LRT）的完整结果。

| 列名 | 含义 |
|------|------|
| `gene_id` | Ensembl 基因 ID（如 ENSMUSG00000...） |
| `gene_name` | 基因符号（如 Hsph1） |
| `baseMean` | 所有样本的平均归一化计数，反映该基因的表达丰度 |
| `log2FoldChange` | LRT 本身不产生有意义的 LFC（此列值参考意义有限） |
| `stat` | 卡方检验统计量，值越大表示组间差异越显著 |
| `pvalue` | 原始 p 值 |
| `padj` | BH 法校正的假发现率（FDR） |

**解读要点**：
- LRT 检验的是"该基因的表达量在四组之间是否有任何差异"（全局检验），而非具体某两组的对比。
- **padj < 0.05** 的基因被视为"组间可变基因"（Group-Variable Genes），是后续分析的核心。
- 与成对差异分析（Wald 检验）相比，LRT 更适合多组设计，能识别具有复杂变化模式（如先升后降）的基因。

#### `LRT_results_sig.csv`

仅保留 padj < 0.05 的 LRT 显著基因子集，是进行挽救分析的基础输入。

---

### 1.3 成对差异表达分析（DEG）

#### `DEG_DB_vs_WT.csv`

DB_Control 组 vs WT_Control 组的 Wald 检验结果（WT 为对照组，log2FoldChange > 0 表示在 DB 中上调）。

#### `DEG_DBTreated_vs_DB.csv`

DB_Treated 组 vs DB_Control 组的 Wald 检验结果（DB_Control 为对照，LFC > 0 表示治疗后上调）。

#### `DEG_DBTreated_vs_WT.csv`

DB_Treated 组 vs WT_Control 组的差异，反映治疗后是否完全恢复至正常水平。

#### `DEG_WTTreated_vs_WT.csv`

WT_Treated 组 vs WT_Control 组的差异，代表药物对健康动物的"副作用"基础线。

**各 DEG 文件列说明**：

| 列名 | 含义 |
|------|------|
| `gene_id` | Ensembl ID |
| `gene_name` | 基因符号 |
| `baseMean` | 平均表达量 |
| `log2FoldChange` | 以 2 为底的倍数变化对数（正值=比照组高，负值=比照组低） |
| `lfcSE` | LFC 的标准误，反映估计精度 |
| `stat` | Wald 统计量 |
| `pvalue` | 原始 p 值 |
| `padj` | FDR 校正 p 值（BH 法） |

**常用筛选标准**：padj < 0.05 且 |log2FoldChange| > 1（即差异倍数 > 2 倍）。

### 1.4 火山图

#### `Volcano_DB_vs_WT.pdf` / `Volcano_DBTreated_vs_DB.pdf`

X 轴为 log2 倍数变化，Y 轴为 -log10(padj)。

**解读要点**：
- **右上角**（正 LFC，高显著性）：在前者（DB/DBTreated）中显著上调的基因。
- **左上角**（负 LFC，高显著性）：在前者中显著下调的基因。
- 点的颜色/大小通常按显著性和变化量区分，顶部标注的是最显著基因的名称。
- 两张火山图对比：`DB_vs_WT` 显示疾病引起的基因变化，`DBTreated_vs_DB` 显示治疗逆转的基因变化。若某基因在两张图上方向相反（疾病中上调、治疗后下调），是挽救型基因的特征。

### 1.5 高变基因热图

#### `HVG_Heatmap_top60.pdf`

取 VST 归一化后组间变异最大的前 60 个基因（来自 LRT 结果 stat 值排序），绘制样本×基因热图。

**解读要点**：
- 颜色代表基因在每个样本中相对于均值的 z-score（蓝色=低，红色=高）。
- 热图右侧/上方的注释条显示样本所属实验组。
- 理想情况下，同组样本聚集在一起，WT、DB、DB_Treated 形成清晰的颜色分块，说明这些基因能有效区分组别。
- 可从此图直观发现"WT→DB 上调、DB_Treated 下调回"或相反趋势的基因。

### 1.6 GO/KEGG 富集分析

**富集对象**：基于 `DEG_DB_vs_WT.csv` 中显著差异基因（padj < 0.05，|LFC| > 0.5）。

#### `GO_BP_results.csv`

GO 生物过程（Biological Process）的超几何检验结果。

| 列名 | 含义 |
|------|------|
| `ID` | GO term ID |
| `Description` | GO term 描述 |
| `GeneRatio` | 输入基因中属于该 term 的比例（k/n） |
| `BgRatio` | 背景基因组中该 term 的比例（M/N） |
| `pvalue` / `p.adjust` | 原始/FDR 校正 p 值 |
| `qvalue` | q 值（另一种 FDR 估计） |
| `geneID` | 属于该 term 的基因列表（"/"分隔） |
| `Count` | 属于该 term 的基因数目 |

#### `GO_BP_dotplot.pdf`

点图，每个点 = 一个 GO term：
- **X 轴**（GeneRatio）：该 term 在输入基因集中的富集比例，越靠右富集越强。
- **点的大小**：基因计数，越大说明该 term 包含的差异基因越多。
- **点的颜色**：p.adjust，越红/深说明越显著。
- **Y 轴**：GO term 名称，通常按 GeneRatio 排序。

#### `GO_BP_emap.pdf`

富集通路关系网络图（emapplot）：
- 每个节点 = 一个显著 GO term，节点大小 = 基因计数，节点颜色 = 显著性。
- 节点间连线 = 两个 term 共享基因比例（Jaccard 系数），连线越粗共享越多。
- 聚集在一起的多个 term 构成一个功能模块，反映疾病/治疗影响的核心通路群。

#### `KEGG_results.csv` / `KEGG_dotplot.pdf`

KEGG 代谢通路富集，格式与 GO 类同。重点关注：免疫相关通路（NOD-like receptor、TNF、NF-κB）、代谢通路（脂质代谢、氧化磷酸化）、屏障功能相关通路（Tight junction）等。

### 1.7 GSEA 基因集富集分析

**结果目录**：`analysis_results/RNA/{site}/GSEA/`

GSEA 不同于过表示分析（ORA），它利用全部基因的排序列表（按 Wald stat 排序），因此能检测到整体性趋势，不依赖任意阈值切分。

#### `GSEA_GOBP_{contrast}.csv` / `GSEA_Hallmark_{contrast}.csv` / `GSEA_KEGG_{contrast}.csv`

| 列名 | 含义 |
|------|------|
| `ID` / `Description` | 通路名称 |
| `NES` | 标准化富集得分。NES > 0 表示该通路基因整体在分子排序前端（即在比较组中上调），NES < 0 表示整体下调 |
| `pvalue` / `p.adjust` | 置换检验 p 值及 FDR |
| `core_enrichment` | 核心贡献基因（"/"分隔），即推动 NES 得分的关键基因 |

**解读要点**：
- 重点关注 `DB_vs_WT` 对比：NES 大的正向通路 = 糖尿病激活通路；负向通路 = 疾病中受抑制的通路。
- 重点关注 `DBTreated_vs_DB` 对比：NES 方向与 `DB_vs_WT` 中**相反**的通路 = 药物直接逆转的通路，生物学意义最强。
- Hallmark 基因集（MSigDB C2）为概括性通路，如 HALLMARK_INFLAMMATORY_RESPONSE、HALLMARK_OXIDATIVE_PHOSPHORYLATION，直接反映疾病/治疗的整体效应方向。

#### `GSEA_{pathway}_{contrast}_barplot.pdf`

条形图，展示显著通路的 NES 得分，颜色区分激活（红）与抑制（蓝）。

#### `GSEA_{pathway}_{contrast}_focus_enrichcurve.pdf`

富集曲线图（Running Enrichment Score），针对炎症/上皮屏障/细胞因子等重点通路单独展示：
- **X 轴**：基因按 Wald stat 从高到低的排列顺序。
- **Y 轴**：累积富集得分（ES）。
- 曲线偏向左侧（高排名）且 ES 为正 = 通路基因聚集在上调区域 = 正向激活。
- 曲线偏向右侧且 ES 为负 = 通路基因聚集在下调区域 = 负向抑制。
- 曲线底部的竖线标记（Leading Edge）指示哪些基因对 NES 贡献最大。

## 第二部分：挽救基因分析 {#part2}

**结果目录**：`analysis_results/RNA/Rescue/{Lung,BO,Oral}/`

**定义**："挽救基因"是指在 WT→DB 过程中发生显著改变，而在 DB→DB_Treated 过程中出现反向恢复的基因，体现了索马鲁肽的治疗效果。

---

### 2.1 方法 A：DEG 交集法

#### `A_rescue_all_genes.csv` / `A_rescue_sig_genes.csv`

| 列名 | 含义 |
|------|------|
| `gene_id` / `gene_name` | 基因标识 |
| `lfc_db_wt` | DB_Control vs WT_Control 的 LFC（正值=DB 中上调） |
| `padj_db_wt` | 疾病效应的显著性 |
| `lfc_trt_db` | DB_Treated vs DB_Control 的 LFC（正值=治疗后上调） |
| `padj_trt_db` | 治疗效应的显著性 |
| `lfc_trt_wt` | DB_Treated vs WT_Control 的 LFC（衡量恢复是否完全） |
| `padj_trt_wt` | 恢复完整性的显著性 |
| `rescue_pct` | 恢复百分比（lfc_trt_db / lfc_db_wt × 100%），>100% 为过度恢复 |
| `rescue_type` | Complete Rescue（完全恢复）/ Partial Rescue（部分恢复）等分类 |

**`A_rescue_sig_genes.csv`** 筛选标准：
1. DB_vs_WT 显著（padj < 0.05）
2. DBTreated_vs_DB 方向与 DB_vs_WT 相反（LFC 符号相反）
3. DBTreated_vs_DB 也显著（padj < 0.05）

这是最严格的挽救基因定义，要求两个对比均统计显著。

---

### 2.2 方法 B：挽救得分法

#### `B_rescue_score_all.csv`

| 列名 | 含义 |
|------|------|
| `gene_id` / `gene_name` | 基因标识 |
| `lfc_db_wt` | 疾病效应 LFC |
| `lfc_trt_db` | 治疗效应 LFC |
| `rescue_score` | 挽救得分 = -lfc_trt_db / lfc_db_wt |

**挽救得分解读**：
- `rescue_score = 1.0`：治疗完全逆转了疾病引起的变化（完美恢复）。
- `rescue_score = 0.5`：治疗逆转了 50% 的疾病变化（部分恢复）。
- `rescue_score > 1.0`：过度矫正，治疗后表达量超过了正常水平。
- `rescue_score < 0`：治疗后变化方向与预期相反（可能加重）。
- 该方法不依赖显著性阈值，适合后续 GSEA 用挽救得分排序分析哪些通路得到了整体恢复。

#### `B_LFC_scatter_rescue.pdf`

散点图，X 轴为 `lfc_db_wt`，Y 轴为 `lfc_trt_db`：
- **第二象限**（X<0, Y>0）：疾病中下调、治疗后上调 = 典型挽救型。
- **第四象限**（X>0, Y<0）：疾病中上调、治疗后下调 = 典型挽救型。
- 位于这两个象限的点是最典型的挽救基因，它们关于原点形成斜线（如果是等比例恢复则在斜率 = -1 的直线上）。

---

### 2.3 方法 C：K-means 聚类法（主要方法）

#### `C_kmeans_cluster_summary.csv`

K-means 聚类（k=6）对所有 LRT 显著基因按 WT/DB/DBTreated 三组 VST 均值进行聚类后，各簇的汇总信息。

| 列名 | 含义 |
|------|------|
| `WT_Control` | 该簇基因在 WT 组的平均 VST 值（z-score 标准化后） |
| `DB_Control` | 该簇基因在 DB 组的平均 VST 值 |
| `DB_Treated` | 该簇基因在 DB_Treated 组的平均 VST 值 |
| `cluster` | 簇编号（1-6） |
| `n_genes` | 该簇包含的基因数量 |
| `disease_dir` | 疾病方向：1 = 疾病时上调，-1 = 疾病时下调 |
| `is_rescue` | 是否符合挽救趋势（TRUE/FALSE） |
| `rescue_mag` | 是否有足够的恢复幅度（TRUE/FALSE） |

**识别挽救簇**：同时满足 `is_rescue = TRUE` 且 `rescue_mag = TRUE` 的簇即为挽救簇。

典型挽救模式：
- **疾病上调-治疗下调**：WT_mean 低 → DB_mean 高 → DB_Treated_mean 中间/低（disease_dir = 1）
- **疾病下调-治疗上调**：WT_mean 高 → DB_mean 低 → DB_Treated_mean 中间/高（disease_dir = -1）

#### `C_kmeans_pattern_plot.pdf`

折线图，展示每个 cluster 的平均表达模式（X 轴：WT → DB → DB_Treated 三组，Y 轴：标准化 VST 均值）：
- 带有"先升后降"或"先降后升"折线形状的簇即为挽救簇。
- 折线颜色/标注注明了是否为挽救簇及基因数量。

#### `C_rescue_cluster_genes.csv`

所有挽救簇成员基因的详细信息。

| 列名 | 含义 |
|------|------|
| `gene_id` / `gene_name` | 基因标识 |
| `cluster` | 所属挽救簇编号 |
| `baseMean` | 平均表达量（来自 LRT 结果） |
| `log2FoldChange` | LRT 的总体 LFC（参考意义有限） |
| `stat` | LRT 卡方统计量（越高 = 组间变化越大） |
| `pvalue` / `padj` | 显著性 |

#### `C_rescue_cluster_heatmap.pdf`

仅包含挽救簇基因的样本×基因热图（按 cluster 分组展示），可直观看到挽救型基因在三组间的表达变化模式。

#### `C_rescue_cluster_GO_BP.csv` / `C_rescue_cluster_GO_BP_dotplot.pdf`

挽救簇基因的 GO 富集分析，揭示挽救型基因主要涉及哪些生物过程（如免疫调节、上皮完整性、细胞因子信号等）。

### 2.4 挽救基因 GSEA

**目录**：`Rescue/{site}/GSEA/`

#### `GSEA_Rescue_GOBP_{site}.csv` 等

使用**挽救得分**（方法 B 的 rescue_score）作为基因排序指标，对所有 LRT 显著基因进行 GSEA，识别整体上被治疗"恢复"的生物通路。

**解读**：
- NES > 0 的通路 = 这些通路的基因整体具有高挽救得分 = 该通路被药物整体恢复。
- NES < 0 的通路 = 该通路的基因整体未被恢复（甚至进一步偏离正常水平）。
- 与常规 GSEA（按差异统计量排序）相比，这里的排序依据是"恢复程度"，结果直接反映治疗的功能性效果。

## 第三部分：宿主-微生物组联合分析 {#part3}

**结果目录**：`analysis_results/Joint/{Lung,BO,Oral}/`

**分析逻辑**：将方法 C 得到的挽救基因簇（每个簇计算特征值 Eigengene = 该簇基因 VST 矩阵的第一主成分）与 16S 扩增子测序得到的菌属 CLR 丰度进行 Spearman 相关分析。

---

### 3.1 挽救菌属鉴定

#### `genus_rescue_score_all.csv`

所有菌属的 CLR（中心对数比变换）均值及挽救得分。

| 列名 | 含义 |
|------|------|
| `Genus` | 菌属名称 |
| `mean_wt` | WT 组的 CLR 均值 |
| `mean_db` | DB 组的 CLR 均值 |
| `mean_trt` | DB_Treated 组的 CLR 均值 |
| `delta_disease` | 疾病效应：mean_db - mean_wt（正值=疾病中增多） |
| `delta_treat` | 治疗效应：mean_trt - mean_db（正值=治疗后增多） |
| `rescue_score` | 挽救得分 = -delta_treat / delta_disease（同基因挽救得分逻辑） |
| `is_rescue_dir` | 方向是否符合挽救趋势（TRUE/FALSE） |

CLR 变换说明：CLR = log(x/geometric_mean)，消除了成分数据的总量约束，值的大小可比较。

#### `rescue_genus_list.csv`

筛选后的挽救菌属列表。筛选标准：
1. |delta_disease| >= 0.3（疾病引起足够大的变化）
2. rescue_score >= 0.3（治疗逆转至少 30%）
3. is_rescue_dir = TRUE（方向正确）

#### `genus_rescue_scatter.pdf`

散点图，X 轴为 delta_disease，Y 轴为 delta_treat，每个点代表一个菌属：
- **第二象限**（疾病减少-治疗后增加）和**第四象限**（疾病增加-治疗后减少）= 挽救型菌属。
- 颜色标注是否为挽救菌属，标签显示菌属名。

---

### 3.2 宿主模块特征值

#### `eigengene_values.csv`

每个样本在每个挽救基因簇的特征值（Eigengene）。

| 列名 | 含义 |
|------|------|
| `EG_DB_up` | 疾病中上调型簇的特征值（该样本在此模块的整体表达水平） |

## 附录：分析方法说明

### VST 归一化

方差稳定变换（Variance Stabilizing Transformation），DESeq2 对原始计数数据进行的归一化处理，目的是消除高计数基因的方差优势，使不同表达量基因的变异性可比，适合 PCA、热图等可视化分析。

### LRT vs Wald 检验

- **Wald 检验**：检验特定两组间是否有差异，每次针对一个具体对比（如 DB vs WT），适合成对比较，输出 LFC 有明确生物学意义。
- **LRT（似然比检验）**：比较完整模型（~Group）与缩减模型（~1），检验"组别"变量是否对该基因的表达有任何解释力，是多组设计（≥3 组）中检测组间变异基因的正确方法。LRT 不输出成对 LFC，但对发现复杂变化模式（如先升后降的挽救型基因）更敏感。

### CLR 变换

中心对数比（Centered Log-Ratio），标准的成分数据变换方法。公式：CLR(x) = log(x / g(x))，其中 g(x) 为该样本所有菌属相对丰度的几何均值。CLR 变换消除了成分数据的总量约束，使丰度值可以进行标准的相关性分析和差异分析。

### Eigengene（特征值）

对基因模块（一组基因的 VST 表达矩阵）进行 PCA，取第一主成分（PC1）的样本得分作为该模块的代表性特征值。其数学意义：解释该模块内基因最大共同变异方向的综合指标。等同于 WGCNA 中的 Module Eigengene（ME）概念，但这里应用于预定义的挽救基因簇。

### MedianCLV 菌群紊乱指数

由 dysbiosisR 包实现。以健康对照组（WT）样本的菌群组成为参照，计算每个样本基于 Aitchison 距离（CLR 欧几里得距离）偏离参照群的中位距离。值越大代表菌群越偏离正常状态（越紊乱）。
